# 日志解释与隧道核验

## 日志解释边界

Web Console 的“智能解释”是本地规则解释，不调用在线翻译服务，也不会改写原始日志。每条记录同时保留：

- 原始日志：用于排障和复制给维护者。
- 严重级别：`info`、`warning`、`error`、`critical`。
- 中文译解：说明该类日志通常代表什么。
- 建议动作：只在有明确下一步时显示。

规则优先识别启动、优雅停止、备份、更新、玩家进出、超时、端口占用、权限、磁盘不足、OOM、存档加载和崩溃。无法确定具体原因的错误仍标为“通用错误”，不会编造原因。

`error` 和 `critical` 会自动去重写入：

```text
data/diagnostics/incidents.jsonl
```

记录会遮盖 Webhook、令牌、密码和 IPv4 最后一段。Web Console 每次刷新日志以及仪表盘采样时都会执行扫描，因此不要求用户一直停留在日志页面。

## 每日完整归档

独立进程 `scripts/daily-log-collector.ps1` 每 60 秒生成：

```text
data/log-archive/YYYY-MM-DD.txt
```

日期边界固定为北京时间 00:00:00–24:00:00。文件分为 Docker 游戏容器、Windows
原生生命周期、Windows 引擎尽力输出、Web Console 操作、SakuraFrp 服务和自动
异常记录六个区段。Docker 的 UTC 时间戳转换为
北京时间，终端颜色控制符会清除；SakuraFrp 运行中锁定的文件使用共享读取，不会
中断隧道服务。游戏日志先合并到 `data/log-sources/game/YYYY-MM-DD.log`，用
包含时间戳的完整行去重，防止当天重建容器或 Docker 日志轮转后覆盖旧记录。跨日
时先封存旧日再创建新日，启动时回补前一日，正常停止后执行最终刷新。

归档不自动删除，也不上传。与经过遮蔽的事件摘要不同，完整归档可能保留玩家名称、
标识和 IP，目的是本机复盘；对外发送前必须人工检查。

## SakuraFrp 证据链

“验证隧道”依次检查五层证据：

1. Docker 是否在宿主机发布游戏 UDP 端口。
2. SakuraLauncher、SakuraFrpService 或 frpc 进程是否存在。
3. frpc 是否与节点保持已建立的 TCP 控制连接。
4. SakuraFrp 服务日志是否出现“隧道启动成功”并给出远程地址。
5. 启动成功之后是否出现成功的外部数据连接或流量证据。

只有五层全部通过且没有仍处于实时窗口的连接错误，状态才显示“外部数据连接已
验证”。“进程存在”“节点控制连接已建立”或“隧道启动成功”都不能单独证明
朋友已经能够进入游戏。

网络端点和 TCP 控制连接由独立、最多 2.5 秒的本地探针读取，避免 Windows 的
NetTCPIP/WMI 查询阻塞整个单线程 Web Console。探针超时或不可用时状态为
`network-unobserved`：控制连接和 UDP 都是“未观察到”，不能写成“已断开”，也不能
作为隧道已就绪或已验证的证据。

数据连接错误的实时窗口为 15 分钟。错误发生在最近一次代理就绪之后且未超过
15 分钟时，状态为 `degraded`；超过窗口后仍保留原文、时间和事件档案，但若
本地 UDP、控制连接和代理仍正常，当前状态恢复为 `ready`。这一区分避免单次旧
超时让“需要注意”永久存在，同时没有把历史错误删除或误报成端到端已验证。

## 2026-07-28 历史证据

- `11:57:41`：连接节点成功。
- `11:57:41`：UDP 隧道启动成功。
- 历史远程地址已从公开源码中移除；远程地址属于部署私密数据，不能作为示例、文档或发布材料。
- `11:57:51`：新数据连接建立失败，`dial tcp 198.18.0.xxx:8088: i/o timeout`。
- 当前 frpc 到节点的控制连接存在，Docker 也发布了 UDP 8211；该超时已超过
  15 分钟实时窗口。
- 没有成功外部数据流量证据。

当时状态为“隧道已启动，等待外部验证”（`ready`），不是“数据连接异常”
也不是“已验证”。11:57:51 的记录是历史异常：它表示 frpc 为一次转发尝试建立
节点数据通道时没有在期限内完成。若新测试再次在 15 分钟内出现同类错误，面板会
重新进入 `degraded` 并显示“需要注意”；若每次测试都出现，应优先更换
SakuraFrp 节点或网络，再核对本地目标是否仍为 `127.0.0.1:8211/UDP`。

## 2026-07-31 当前证据

本轮 Windows 实测中，受限网络探针未在时限内完成，因此实时状态为
`network-unobserved`。这既不证明本机 UDP 未监听，也不证明 frpc 控制连接已经
断开；当前远程端点和成功外部流量仍未被观察到。旧的历史远程地址只能作为本机
私有记录，不能给朋友作为当前连接地址，也不能作为远端可达性的证据。

## 人工端到端验证

1. 保持 Palworld 容器和 SakuraFrp 隧道运行。
2. 在 SakuraFrp Launcher 恢复节点控制连接，并在概览点击“验证隧道”，确认前四层通过。
3. 使用该次检查报告的当前远程地址让外部网络中的朋友连接；不要在同一主机上用远程地址代替 `127.0.0.1:8211`。
4. 朋友尝试连接后再次点击“验证隧道”。
5. 只有出现成功外部数据流量并能进入服务器，才完成端到端验证。
