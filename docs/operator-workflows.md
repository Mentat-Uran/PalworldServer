# 控制台常用操作指南

本指南面向不熟悉 Palworld 后台指令的本机管理员。Web Console 只允许通过
`localhost`、`127.0.0.1` 或 `[::1]` 使用；不要把它、REST 或 RCON 通过隧道、
端口转发或反向代理公开。

## 从概览开始

概览页的“从这里开始”按日常目标组织，而不是按底层命令组织：

| 目标 | 会发生什么 | 不会发生什么 |
|---|---|---|
| 保存世界 | 向当前运行时请求 REST 保存 | 不停止服务 |
| 创建备份 | 先保存，再由当前运行时创建本地归档 | 不验证生产恢复能力 |
| 查看或管理玩家 | 定位到实时玩家表 | 不执行玩家管理指令 |
| 检查好友能否加入 | 刷新本地、控制、代理和流量证据 | 不代替真实远端加入测试 |
| 排查问题 | 打开带说明与建议的日志 | 不自动修复或重启服务 |

涉及停服、重启或切换时，先完成“保存世界 → 创建备份”。备份文件存在只能证明归档
已经创建，不能证明生产世界可以恢复。

## 玩家管理与 RCON

RCON 仅为兼容性终端；保存和玩家读取优先使用 REST。面板的“按目标操作”允许：

1. 回到概览读取实时在线玩家；
2. 在目标玩家行点击 Steam ID 或 Player UID 的“填入指令”；
3. 选择一个快捷模板或生成公告，检查输入框后再手动发送。

点击 ID 不会执行命令。原始 ID 仅保存在当前页面内存中，表格 HTML 属性、浏览器存储
和 Web Console 操作日志都不记录该值。模板里的 `<steamid>`、`<playeruid>`、
`<playerid>` 或 `<userid>` 会优先被所选 ID 替换；没有占位符时，ID 会插入当前光标位置。

`kickplayer`、`banplayer`、`unbanplayer`、`shutdown` 和 `doexit` 在发送前会显示二次
确认。确认只是防误操作，并不验证玩家选择、远端通知、备份可恢复性或多人运行结果。

## 运行时差异

Web Console 会按 `data\runtime.state` 的活动运行时路由操作。Windows 原生运行时使用
本机 Windows RCON；Docker 运行时使用容器内 `rcon-cli`。两种运行时共用世界存档且必须
互斥运行。切换或恢复仍应遵循维护窗口运行手册，而不是依赖面板按钮本身作为安全证明。

## 维护者检查

以下检查不需要运行浏览器或游戏服务器：

```powershell
node .\scripts\test-i18n-parity.cjs
node .\scripts\test-player-command-picker.cjs
node .\scripts\test-console-guided-actions.cjs
```

它们验证双语字典、ID 不进入 HTML 属性、Windows RCON 路由、引导入口和高风险指令确认
的源码契约；并不替代真实玩家、远端隧道或恢复测试。
